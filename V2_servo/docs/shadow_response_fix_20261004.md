# 数字孪生机械臂慢、卡顿：诊断与修复（2026-10-04）

结论：旧代码把机械臂状态发布放在 200 ms 的文字刷新分支，导致画面约 5 Hz 跳动；影子参数低速且跟随增益较小，造成明显追手落后。已经修复并重新构建同一 V2Twin。入口仍为根目录 START_V2.cmd。

## 本轮实际来源

用户会话 `data/continuous_quest_20261004_130954_693706/`：100.587 秒、12568 个周期、5602 个 FOLLOW 样本，模拟最大 TCP 位移 180.393 mm，无控制故障；实际 Quest 输入被记录，但机器人反馈为理想模拟，真实机器人命令数 0。

周期 P50/P95/P99 约 8.000/8.013/8.071 ms，最大 8.627 ms；这不支持“控制循环本身每200ms卡一次”的判断。Unity 代码只有收到状态才应用关节角，Python 却每200ms才发一次，才是画面台阶的直接来源。

会话共收到 6877 包、解码 6324、拒绝 553；结束时错误为 grip_available 缺失，且记录了一次追踪超时减速。缺追踪时锁停不能通过放松检查消除，也不能把它混同为显示刷新卡顿。

## 修改

- `continuous_shadow.py`：每个8ms周期向原有独立UDP最新槽发送模拟关节状态，文字仍5Hz，不新增关节插值或伪造实际反馈。
- `shadow_telemetry.py`：文字提示/status.json改由有界最新槽的后台线程写入；慢文件I/O不阻塞规划。
- `config/continuous.json`：只改影子配置。请求线速度30→120mm/s、角速度0.25→0.5rad/s、关节速度6→30°/s、加速度30→120°/s²、jerk120→600°/s³、位置/姿态增益2→6。位移倍率1、旋转倍率0.5不变，默认低通/Ruckig/关节边界/追踪停止保持。
- Unity 增加仅在显式诊断变量下启用的更新计时探针；模拟状态标题明确标记“非实机反馈”。没有改变原生相机交互或重做场景。

## 回归、使用、回滚

23项相关回归通过，含新慢文件写入不阻塞UDP测试；实际统一入口启动/停止检查通过，1247个周期分别提供1247次孪生更新、50次文字写入，最新槽替换0。该自动检查没有有效手柄追踪，只算进程/传输通过。

现在：停止影子→正常关闭旧 V2Twin 和主窗口→双击根目录 START_V2.cmd→连续遥操作影子→先松Grip、再握持自然移动。默认即新参数，不换入口、不重新逐轴。仍是模拟模式，不发送机器人运动。

旧配置/源码/DLL备份和SHA256在 `data/shadow_response_fix_20261004/before/`、`before_manifest.json`。要回到旧慢档可停止进程后恢复其中的 config/continuous.json；这不影响已修复的高频显示。完整回滚可恢复相应源码后重新构建。历史用户原始会话不修改。

真机控制核、真机限速/滤波配置未放宽；连续真机未放行。旧版、V1.5、F盘源未修改。

- get_actual_joint_position：1473次，最大约4.02ms，返回均为0。
- get_actual_tcp_position：1473次，最大约4.37ms，返回均为0。
- is_on_limit：第369次调用耗时25000.9ms，返回-1（SDK头文件定义invalid handler）。
- SDK调用5529在12:39:41.282开始，12:40:06.283结束。
- 运动命令数0；未尝试运动停止（没有本程序发起的运动），最后正常logout。
- ①的TCP连接创建时间为12:39:43，说明该读取进程在故障期间重新建立过连接。

结论：无需手柄输入、逆解或运动，就能复现25秒阻塞。
尚不能断言由哪一个客户端、某个特定读取接口、网络、SDK或控制器造成。
①重连时间与②阻塞重叠，是相关性证据，不足以证明“logout踢掉另一客户端”。
## ①关闭后的单连接对照（17:30）

确认①的 Unity/只读桥进程已退出；仅发现一个旧② GUI 进程，但它没有到 JAKA 控制器的 TCP 连接。随后直接运行相同的 `--comm-check --session-seconds 30`，没有打开①，也没有启动运动会话。

报告：`continuous_sampled_follow/session_20260923_173052_243211.jsonl`；逐调用：同名 `.sdk.jsonl`。

- 30.0015 秒完成 1794 组关节/TCP 读取，实测约 59.80 Hz；运动命令数 0。

这是一组相关性证据，不是多客户端必然冲突的证明，也不能证明①的重新连接导致 SDK 句柄失效。单连接 30 秒只读通过，更不能推导出 `linear_move_extend` 调用、停止确认或真机运动安全。下一步应隔离①和②的控制器 SDK 连接生命周期，并保留数字孪生的实测反馈通道；在只读压力测试与现场停止确认通过前，不以本次结果放行真机跟随。

## 单连接显示链路改造与只读验收（18:01）

已将根目录①改为 `--vr-only`：只启动 Unity，不创建 SDK 对象。②持有本机 SDK 独占闸门，使用同一个机器人句柄把真实关节和 TCP 反馈经 UDP 5006 广播给 Unity；手柄黄色目标仍走独立显示绑定。旧①的 `--live-readonly` 诊断入口保留，但也要求取得独占闸门，不能与②同时使用。这个闸门只约束本项目的新进程，不约束厂商上位机、旧运行进程或其它电脑。

根目录①没有开启时，运行 `--comm-check --single-owner-display --session-seconds 30`，报告 `continuous_sampled_follow/session_20260923_180119_319861.jsonl`：

- 30.014 秒完成 1785 组基础只读状态，约 59.47 Hz；同时执行显示反馈的只读关节/TCP采样。
- 共 8149 次 SDK 调用；返回错误 0、迟到调用 0；除登录/注销外，最长一次 `is_in_collision` 为 11.05 ms。
- 运动命令数 0，最后正常注销；测试后未发现活动的 JAKA 连接。
- 离线测试包含同句柄实测包、本机 UDP 编解码、第二连接闸门拒绝、VR-only 不加载SDK、假SDK运动路径。

这仅确认新架构的通信和数据契约，**尚未在 Unity 实际画面中观察动态关节帧，也没有进行新架构真机运动测试**。以前独立只读桥的根因仍未查明；不能据此宣称运动风险已消失。

## 待现场执行：一次≤5mm单段真机验收

新增独立按钮与运行器 `--one-segment-acceptance`：固定速度5mm/s、加速度10mm/s²、活动半径20mm、单段≤5mm、目标死区3mm、会话最长30秒。`--live` 无该标志会在连接SDK之前拒绝；按钮在启动前要求操作者确认现场条件。单段命令后不再规划下一段，只有实测TCP误差≤1mm且SDK报告运动完成才标记 `acceptance_complete`；松Grip/输入失效/异常则中止并记为 `acceptance_incomplete`，异常后的GUI禁止一键重试。

离线假SDK测试包括“恰好一条≤5mm、速度/加速度固定的下发并自动结束”“松Grip中止且不重试”“第二道命令条数闸门拒绝下发”“连续模式启动前拒绝”“真实Tk界面弹窗及参数路径”；38项Python单元/集成测试和真实Tk离线窗口测试通过。**这些测试未向控制器发出运动；现场方向、动态数字孪生、到位与保护停机表现仍未知。**

## 已完成代码修复与离线证据

- 每次SDK调用先记录begin，再记录end、耗时、返回码，滚动限长。普通调用返回超过150ms拒绝迟到结果；仅保留停止/确认/注销清理接口。
- GUI独立监视调用进度；普通调用约0.3秒未返回则提示具体方法并撤销许可。不宣称能中断原生阻塞或保证硬实时停止。
- 新增只读通信检查按钮；测试即使机器未使能也不做上电或使能操作。
- Unity接收独立显示绑定，本地XR每帧绘制黄色目标；不等待SDK，不影响实测关节。

- 松Grip/丢追踪使本地绑定失效；旧绑定重发不恢复，新绑定可恢复。
- 31项Python测试通过（SDK包装4、跟随18、运行器3、只读桥6）；真实Tk窗口参数/停止锁定/阻塞提示检查通过。
- Unity本地目标、旧绑定拒绝、新绑定恢复、实测中间帧验证和Windows构建通过。
- Player_通信修复为独立输出，未覆盖正在运行的旧Player；①已指向新输出，下次重开生效。

这不是通信故障已解决或真机运动已验收的报告。先完成单/双客户端只读对照，再决定后续修复；不增加速度、不放宽限位、不重启控制柜、不自动重发旧运动。

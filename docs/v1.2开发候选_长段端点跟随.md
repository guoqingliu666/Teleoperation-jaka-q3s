# v1.2 开发候选：长段端点跟随

> 状态：开发中、未发布、未经本轮真机验收。`v1.0.0` 标签和已经发布的第一版不变。

## 本轮要解决的问题

第一版的正式六维模式每条命令最多移动 `20 mm / 2°`，并且每条命令都以 `tol=0` 精确到位。机器人会在每个端点减速到停，所以即使单段本身平滑，连续操作仍会感觉离散、停顿频繁。

本候选版没有恢复事故版本的 `servo_j/servo_p`，也没有加入自编逆运动学。它继续使用：

- JAKA 厂商 `kine_inverse` 做整段逐点逆解检查；
- JAKA 厂商 `linear_move_extend_ori` 执行单条六维端点命令；
- 同一时刻最多一条命令在途；
- 松开 Grip、追踪失效、输入过期或健康检查失败时停止，不补跑手柄历史轨迹。

## 已实现的变化

正式六维界面新增两项启动时锁定的参数：

- 单条最大位移：`20—100 mm`，默认 `60 mm`；
- 单条最大姿态：`2—10°`，默认 `6°`。

同时把开发候选的可调范围扩大到：

- TCP 速度：`5—300 mm/s`，默认 `150 mm/s`；
- TCP 加速度：`10—800 mm/s²`，默认 `400 mm/s²`；
- 姿态速度：`1—60°/s`，默认 `30°/s`；
- 活动半径：`20—100 cm`；
- 相对启动姿态：`±10—30°`。

更长的端点段会降低“规划一次、停稳一次”的频率，但它仍是精确到位的单命令模式，不等同于厂商队列圆滑。后续若启用非零 `tol` 和运动队列，必须作为独立门槛验收，不能把离线测试当作真机放行。

## 黄色手柄目标修复

Unity 目标绑定原来只接受 `radius_mm<=200` 和 `rotation_limit_deg<=10`，而正式模式会发送 `1000 mm / 30°`，因此整份绑定会被判无效，明黄色球和工具轴消失。

此外旧字段 `position_only=false` 在六维模式下会阻止目标位置更新。本候选版新增明确的 `position_enabled` 字段：

- 位置跟随和六维跟随：`position_enabled=true`；
- 纯姿态只读影子：`position_enabled=false`。

Unity 现在接受开发候选的 `20—1000 mm` 和 `1—30°` 范围，黄色目标会同时显示手柄映射后的位置与姿态；蓝色坐标仍只表示机器人实测 TCP，二者不得混用。

## 零运动检查入口

②界面新增“`v1.2长段六维只读影子（30秒 / 零运动）`”。它与正式六维按钮读取完全相同的六项参数，但强制使用 `--shadow`：

- 会连接 JAKA 并调用厂商逆解检查；
- 会把黄色目标绑定发送给 Unity；
- 会显示实测关节和蓝色 TCP；
- 不调用任何运动接口，日志中的 `movement_commands_sent` 必须为 `0`。

先用该入口确认黄色球、坐标轴、方向、姿态和活动范围，再决定是否进入单独的受限真机验收。正式六维参数扩大本身不构成真机验收结论。

只读影子通过后，②还提供“`v1.2一次≤60mm/6°真机验收（150mm/s）`”。该入口忽略滑杆，固定使用 `60 mm / 6°、150 mm/s、400 mm/s²、30°/s`，最多下发一条命令；到位后自动结束。它只用于验证开发候选的第一条长段命令，仍不代表连续长段遥操作已经通过。

2026-09-25 现场反馈确认：黄色目标正确显示并同步；单条长段真机动作方向正确、平滑、无关节突变，且无抖动、异响或报警。因此下一关开放“`v1.2连续长段六维验收（150mm/s / 60mm / 6°）`”：固定使用与已通过单条相同的参数，最多运行180秒。

同日连续长段现场反馈：跟随速度明显提高，方向和黄色目标正确，无关节突变、抖动、异响、报警或 SDK 超时；仍可观察到段间停顿。日志和代码确认原因是每条命令都以 `tol=0` 精确到位，而且下一条只在上一条 `is_in_pos` 后下发。

## 两段六维厂商队列圆滑门槛

②界面现新增“`v1.2两段六维厂商圆滑验收（2×30mm/3°）`”。首轮采用固定路径隔离验证队列行为：

- 第一段：基坐标 `+Z 30mm`，同时绕基坐标 Z 轴增加 `3°`；
- 第二段：基坐标 `+X 30mm`，再增加 `3°`；
- TCP `150mm/s、400mm/s²`，姿态 `30°/s、120°/s²`；
- 第一段 `tol=5mm`，第二段 `tol=0`；
- 最多两条厂商队列命令，绝不开放无限预取；
- 两段发送前均按 `2mm / 0.2°` 调用 JAKA `kine_inverse` 检查；
- 未观察到第一段队列忙态、Grip/心跳/追踪失效、队列故障、实测关节偏离已检查包络或末端超时，都会调用厂商 `motion_abort` 并确认队列清空。

该门槛只改变“命令衔接”，不改变已验证的手柄坐标映射、黄色目标绑定或厂商逆解方法。固定两段现场通过后，才能把同样的深度 2 队列机制接入手柄采样；离线回归不能替代本次真机验收。

2026-09-25 固定两段现场结果：第一段转入第二段时停顿明显减少，`+Z → +X` 方向正确，两段姿态旋转连续；无关节突变、抖动、异响、报警或 SDK 超时。由此开放下一道组合门槛“`v1.2手柄两端点圆滑验收（队列2）`”。

组合门槛的行为是：按住 Grip 连续移动时，黄色目标照常实时跟随；相对起点达到 `20mm` 或 `2°` 时采第一个端点，再相对第一点达到 `20mm` 或 `2°` 时采第二个端点。机器人在采样期间保持静止，随后才对两段分别调用厂商逆解并以已经通过的深度 2 队列执行一次：

- 每段硬限制 `≤60mm / 6°`；
- 第一段 `tol=5mm`，第二段 `tol=0`；
- 第二点过近时拒绝，避免把手柄噪声当作路径；
- 采完第二点后，手柄偏离冻结点超过 `30mm / 8°`、Grip 松开、追踪或心跳失效时禁止下发或请求停止；
- 一次只执行两个端点，到位后会话结束，不自动滚动续接。

2026-09-25 手柄两端点现场结果：两段方向都与黄色目标一致，第一段转入第二段连续且停顿明显减少，姿态变化正确；无关节突变、抖动、异响、报警或 SDK 超时。

## 有限滚动深度 2 六维队列

②界面现开放“`v1.2滚动六维圆滑验收（队列2 / 最多10段）`”，把已经通过的两端点机制扩成有限滚动：

- 持续握住 Grip 即连续更新黄色位置/姿态目标，无需 A 键；
- 控制柜中始终最多保留一条执行段和一条预排段；
- 预排槽空出时只采用当时最新目标，不补跑旧手柄轨迹；
- 新端点相对队列尾端至少变化 `20mm` 或 `2°` 才会进入规划；更小目标先合并，避免短段耗尽队列；
- 每条仍经 JAKA `kine_inverse` 以 `2mm / 0.2°` 步长检查，并硬限制 `≤60mm / 6°`；
- 第 1—9 段使用 `tol=5mm` 圆滑衔接，第 10 段使用 `tol=0` 精确到位并自动结束；
- 首条命令必须先观察到控制柜忙态，不能把命令发送后的短暂旧 idle 状态误判为到位；
- 松开 Grip、追踪/心跳失效、状态故障、实测关节偏离已检查路径包络或 4 秒无进展，都会请求厂商 `motion_abort` 并确认停止；
- 松手停止后可重新握持，剩余命令数仍受本次总计 10 段限制。

此入口是下一道受限真机验收，不等同于已经发布的正式无限遥操作；`v1.0.0` 标签保持不变。

### 现场日志复盘后的关键修复

首轮滚动验收虽然完成十条命令且无关节突变、抖动、异响、报警或 SDK 超时，但日志显示 `max_queue=1`，且没有任何 `rolling_pose_handoff`。根因是旧状态机把 `active_queue=1` 误认为“下一条已预排”，于是实际仍接近逐段到位后再发送。

结合本机 SDK 字段和既有固定圆滑实测，正确序列应为：

- 当前段单独运行：`queue=1, active_queue=1`；
- 下一段进入控制柜：`queue=2, active_queue=1`；
- 圆滑交接完成：回到 `queue=1, active_queue=1`。

现已改为按 `queue: 1→2→1` 管理预排槽。现场日志证明固定 `300ms` 规则会把正常的短段队列切换误判成故障，因此 V1.5 候选改为 `20mm / 2°` 合并采样：正常情况仍记录 `queue=2` 和交接；若轮询跨过瞬时 `queue=2`，必须同时看到 `queue=1/active_queue=1` 且实测 TCP 已进入前段端点圆滑容差才能确认晚交接；若队列耗尽，则必须实测到达最后下发目标才能安全重建。4 秒无进展、深度超过 2 或目标不一致仍停止。十段结束仍必须记录至少八次可验证交接，否则不判定连续队列验收通过。最终 `finished` 日志也已修复为记录队列实际下发条数，而不是映射器的零命令计数。该修订作为 V1.5 候选继续验收；V2 的 JAKA 伺服滤波控制链保持隔离，当前不启用。

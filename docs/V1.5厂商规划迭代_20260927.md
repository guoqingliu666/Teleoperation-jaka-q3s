# V1.5 厂商规划迭代（2026-09-27）

本轮保留 `kine_inverse` 与 `linear_move_extend_ori`。V2 的伺服执行器尚未接入。
本轮仅修改代码、执行离线测试，没有连接机器人、修改控制器参数或发送运动命令。

## 网页对话的适用范围

“轨迹采样”不是一种与 Servo 对立的控制接口。V1.5 从手柄输入选择几何关键点，
JAKA 完成运动段的时间规划和插补；段内的厂商逆解点仅用于筛查，不逐点发送 MoveJ。
因此，网页对话关于“密集采样后逐点 MoveJ”的假设不对应本项目的执行链。

JAKA 官方旧版 TCP/IP 文档分别列出了 MoveL 的速度、加速度、转接半径、姿态参数，
以及 Servo 接口的上层规划责任。该文档明确针对控制器 1.7.1/1.7.2；不能将其全部
细节直接当作当前 SDK/固件的实测保证，也不能把 TCP/IP 的角度单位直接套给 Python SDK。

来源：https://www.jaka.com/docs/legacy172/guide/1.7.2/tcpip.html

V1.5 的分工是：手柄轨迹 → 关键位姿合并 → 自适应厂商逆解检查 →
厂商扩展直线运动队列。它具有在线输入与有限预排，但不承诺物理 C2 连续。
V2 可以复用坐标映射、Grip、输入有效性、轨迹几何和日志；周期发送、时间参数化、
滤波及故障停机需另行实现和验证，不能仅把运动函数名称换成 ServoJ。

## 本轮改动

### 动态只读测试与执行共用关键点输入

此前只读路径每帧构建五次参考曲线、计算导数与偏差，然后仅把曲线端点交给前瞻器。
动态执行路径却直接接收映射位姿。这多了一帧等待与不会被厂商接口执行的计算。

动态只读现在直接使用原始映射位姿，仍逐帧维护四元数连续性、旋转弧长和拧转历史。
捕获帧只建立锚点，后续点保留原始接收时间。固定采样对照模式仍保留五次参考研究。
日志 `reference_pipeline=raw_pose_keypoints` 用于确认启用了新版动态链路。
两条路径共用采样/逆解核心；只读仍是虚拟消费且未套用真机的全部范围约束，不能
用只读候选通过来认定实机队列不断供或大姿态已获验收。

### 修正停手后重新移动的合并窗口

旧判断使用“最新输入时间减锚点时间”。锚点若已停留数秒，第一帧微小位移就会
立即触发规划，增加短段碎片。

动态模式改为从第一条未消费输入的接收时间起算合并窗口（原有 80 ms）。
看到不可合并的转折、折返或达到段长上限时提前准备；平滑的小位移最多等待该窗口。
不重置残量年龄，不扩大积压或过期上限，停手的小残量也会被处理。

### 中点先判断，避免计算必然作废的右端点

最新现场只读日志 `readonly_20260926_193101_542152.jsonl` 中，一项任务调用了
153 次逆解、耗时 125 ms 后被丢弃。总会话 409 次 IK，最大单次耗时约 4.43 ms。
这说明不能只看单次 SDK 耗时，细分总量也会占满准备预算；尚不能断定整个失败只由
本轮修复的重复计算造成。

旧顺序固定先解中点再解右端点，即使中点已经满足原有细分条件，仍多解一次右端点，
之后因参考种子改变又重解。新版在中点已确定需要细分时立即细分。中点正常时仍解
右端点并检查曲率；所有最终接受关节解仍来自厂商 SDK，原有风险门槛保持。

日志新增 `avoided_endpoint_calls`。成功计划的会话累计写入
`sampling_summary.avoided_endpoint_calls`，失败任务的计数保留在规划诊断中。
`adaptive_queue_plan` 明确记录 `check_point_count` 和 `motion_command_count=1`，
防止把检查点数误认为运动命令数。

## 已有验证与下一步

确定性测试中，10 mm、高关节变化放大输入：旧顺序 126 次、新顺序 95 次调用，
均接受同样的 64 个检查点，关节解、端点、细分次数完全相同。减少 31 次调用，
约 24.6%；这是测试替身的工作量对照，不是实机吞吐或物理安全结论。

新增覆盖停手重启合并、拐角提前准备、段长触发、小残量处理、动态只读不构造五次
曲线，以及提前细分与旧顺序的接受结果一致性。全套 `verify_*.py` 回归共 393 项，
结果 `OK (expected failures=1)`；保留一项既有预期失败。
另修复 GUI 测试直接执行时依赖其它测试先设置模块路径的问题。

下一步：关闭空闲旧②窗口后重新打开，点击“新轨迹只读测试（120秒，不运动）”，
使用默认 5 mm / 1°检查间隔，做连续转动、停手再动、转折和三次松握。重点读取
候选数、阻断原因、总 IK 调用量、准备耗时、积压峰值和新增省略调用计数。
真实 SDK 只读复测和新候选的实机连续性验证尚未执行；没有发布 GitHub 版本。

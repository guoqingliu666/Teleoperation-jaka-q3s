# v1.5.0 下载与复现

## 本版本实际验证了什么

V1.5 继续使用 JAKA 厂商 `kine_inverse` 和 `linear_move_extend_ori`，没有加入自编逆运动学，也没有使用 `servo_j/servo_p`。新增外围调度负责：

1. 保留短时间手柄意图并按几何变化动态选点；
2. 平滑区少检查、风险区自适应细分，所有关节解仍由 JAKA SDK 给出；
3. 控制柜维持当前段加一条预排段，避免无界队列造成跟随延迟；
4. 计算落后时限制接纳新输入，丢弃未接纳增量，不在之后补跑历史动作；
5. Grip 松开、追踪丢失、界面心跳中断、路径拒绝或控制器异常时停止下发。

2026-09-28 的真机范围是：启动 TCP 周围 100mm、相对姿态 10°、30mm/s、60mm/s²、姿态速度 5°/s、单条最多 20mm/2°、最多 10 条命令。结果为 10/10 段完成、9 次交接、0 次迟交接、0 次队列断供、停止确认成功。操作者确认连续性良好、姿态没有卡住，无报警或异响。

这不是全工作空间、最高速度或任意全姿态的放行结论，也不证明严格的速度/加速度 C2 连续。界面里的 150mm/s 全范围入口仍明确标为“真机待验收”。

## 外部依赖

- Windows 10/11；
- Meta Quest 3S 与可运行 OpenXR 的环境；
- 与现场控制器匹配且有权使用的 JAKA Python SDK；
- JAKA S5 控制器、正确的 Tool 1/用户坐标系 0、负载和限位配置；
- Python 依赖见 `Python/requirements.txt`。

JAKA SDK、控制器配置和第三方模型不因下载本仓库而自动获得或自动匹配。

## 下载后步骤

1. 下载 `v1.5.0` 标签或 Release 源码包，完整解压到 D 盘。
2. 双击 `验证V1.5文件.cmd`。若哈希失败，不进行真机测试，重新下载并完整解压。
3. 复制 `本机配置.example.cmd` 为 `本机配置.cmd`，填写：
   - `QUEST_JAKA_PYTHON`：含 `jkrc` 的 Python；
   - `QUEST_JAKA_HOST`：现场控制柜 IP；
   - `QUEST_JAKA_SDK_DIR`：匹配的 JAKA SDK 目录；
   - `QUEST_JAKA_LIMITS_FILE`：从本机控制器导出的 `usersettings.ini`。
4. 运行①，确认 HUD 中右手为 `TRACKED`，并且机器人姿态来自新鲜的实测关节反馈。
5. 运行②，先做“只读通信检查”和“中等幅同参数只读预检（60秒，不运动）”。只读成功不等于允许运动。
6. 操作者在 JAKA App 上电并使能；确认机械臂静止无报警、整条机械臂扫掠区域净空、人员在外、急停可触及。
7. 点击“V1.5已验收中等幅跟随（10cm/10°）”，首次先松开 Grip，再握持并缓慢移动。方向、关节、声音或报警任何一项异常都立即松开 Grip，并按现场规程使用急停。

## 正常结束的日志判据

本机日志默认写入被 Git 忽略的 `Validation/continuous_sampled_follow/`。一次完整的固定验收至少应满足：

- `movement_commands_sent=10`；
- `completed_segments=10`；
- `handoff_count=9`；
- `late_handoff_count=0`；
- `starvation_count=0`；
- `stop_confirmed=true`；
- `failure=null`。

这些数值只能证明本次受限会话按设计结束。最终仍要由现场人员确认方向、连续性、关节是否突变，以及有无抖动、异响和报警。

## 版本边界

- V1.5：动态采样 + 厂商逆解 + 厂商笛卡尔圆滑队列。
- V2：另行研究 `servo_j` 和 JAKA 伺服滤波；必须重新从静态保持和固定轴小动作开始验收，不能继承 V1.5 的放行结论。

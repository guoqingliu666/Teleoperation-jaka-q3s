# V1.5 发布门槛：JAKA 厂商队列六维遥操作

> 当前状态：`v1.5.0` 发布收口。已通过的是固定中等幅动态采样模式；150mm/s、100cm、全朝向入口仍是开发候选。V1.5 只使用 JAKA 厂商逆解与笛卡尔圆滑队列；V2 的伺服滤波控制链不进入本版本。

## V1.5 控制方法

- 手柄 Grip 建立相对位姿绑定，黄色球与坐标轴持续显示最新目标；
- 每段调用 JAKA `kine_inverse` 做自适应路径检查：平滑处最大检查间隔 `5mm / 1°`，局部风险处递归细分至最小 `0.25mm / 0.05°`；
- 使用 JAKA `linear_move_extend_ori`，不使用 `servo_j/servo_p`；
- 控制柜最多保留一条当前段和一条预排段；
- 相对队列尾端不足 `20mm` 且不足 `2°` 的目标先合并，避免把手柄细微噪声变成无法维持速度的碎片段；
- 通常以实测 `queue=2` 确认预排、`queue: 2→1` 确认圆滑交接；若状态轮询恰好跨过短暂的 `queue=2` 窗口，只能在 `queue=1/active_queue=1` 且实测 TCP 已进入前段端点圆滑容差时确认交接；
- 队列自然耗尽时，只有实测 TCP 已到最后下发目标才允许从该实测点安全重建；4 秒无进展或队列空闲但目标不一致仍停止；
- 2026-09-25 十段现场基线完成：10/10 段、累计指令位移约 `184.6mm`、累计姿态约 `34.0°`，观察到 8 次 `queue=2`、9 次连续交接（其中 1 次由实测端点确认的晚交接），无队列耗尽，正常停止；
- 50 段扩展验收已经通过；正式连续档不再因命令数达到 50 自动结束，最长会话 30 分钟，松开 Grip 停止确认后可再次握持，并从新的实测 TCP 重新建立相对绑定；
- 正式连续档仍固定使用 `150mm/s、400mm/s²、60mm/6°、20mm/2°合并采样`，启动 TCP 周围 100cm 软件包络；扩展的是累计可运行范围，不提高单段运动强度；
- 新增“姿态优先”档：XYZ 仍按手柄相对位移 `1:1` 跟随，但目标限制在启动 TCP 周围 `100mm` 半径内；姿态累计范围保持 `±30°`，每个厂商队列段最多 `3°`。它不是绝对锁死 XYZ，适合接触物体时做小范围位置修正和较大姿态调整；
- 2026-09-26 姿态优先档完成首轮真机验证：操作者确认三次 Grip 均能重新运动，大姿态/小位置调整符合预期，无顿挫、关节突变、异响、报警或 SDK 超时；对应日志在会话仍保持打开时已记录 `132` 条运动命令、约 `128` 个实测完成段且未出现逆解候选拒绝，证明不再受 50 段自动结束限制；
- 下一档为独立的“扩展姿态优先”门槛：XYZ 子范围 `300mm`、姿态 `±45°`、TCP `200mm/s`、加速度 `500mm/s²`、姿态速度 `45°/s`、单段最多 `80mm/4°`。旧的 `100mm/±30°/150mm/s` 入口保留为已验证回退档；扩展档尚需现场确认，不能从上一档的通过结果自动推定；
- 预排槽空出时只采用最新目标，不补跑历史手柄轨迹；
- 10/50 段验收档只有最后一段 `tol=0` 精确停止；正式连续档的运动段保持 `tol=5mm`，Grip 松开或会话结束时统一调用厂商停止并确认队列清空；
- 未下发前由厂商逆解检查拒绝的候选目标只记录并丢弃，`0.2s` 后继续采用最新手柄目标，不再把一次坏候选误判为整个会话故障；
- Grip 松开、追踪/心跳失效、队列异常、控制器碰撞/报警、停止未确认或实测关节偏离路径包络时仍请求厂商停止；真实控制器故障不会被自动忽略。

## 2026-09-28 动态采样中等幅真机结果

- 固定参数：启动 TCP 周围 `100mm`、相对姿态 `10°`、`30mm/s`、`60mm/s²`、姿态 `5°/s`、单条最多 `20mm / 2°`；
- 只读同参数预检：240 个候选，0 个阻断窗口；最大规划积压约 `140ms`，最大单次规划准备约 `32ms`，没有运动命令；
- 真机：10/10 条运动命令全部完成，9 次厂商队列交接，`late_handoff_count=0`、`starvation_count=0`、`max_queue=2`；
- `stop_confirmed=true`、`failure=null`，SDK 跟踪记录没有迟到调用或错误返回；
- 操作者确认连续性良好、姿态没有卡住，无报警或异响；
- 快速输入超过接纳能力时，未接纳增量立即丢弃且不会排队补跑。黄色目标表示手柄意图，不等同于已接纳或已经到位；松开并重新握持可重建相对绑定。

以上只放行②中的“V1.5已验收中等幅跟随（10cm/10°）”。不自动放行 150mm/s、100cm、全朝向候选，也不证明任意姿态可达或物理轨迹达到严格 C2 连续。

## 2026-09-26 重复 Grip 失效诊断

现场日志中并没有任何一次达到 50 条命令。会话分别因“六维短段累计关节变化超过12°”候选拒绝、一次 J5 碰撞状态以及一次 `motion_abort` 调用超时退出。修复后的边界是：

- **尚未下发的候选路径不合格**：丢弃本次目标，会话继续；
- **松开 Grip**：调用厂商停止，确认空闲后允许再次握持；
- **控制柜碰撞、报警、队列异常、SDK 停止超时**：结束会话并保留停止锁，不自动重试。

离线回归覆盖了超过 50 条仍不自动结束、松开/再握 Grip 后恢复下发、坏候选跳过后继续，以及姿态优先档 `100mm + ±30°` 的独立位置/姿态包络。离线测试不能替代下一次现场验证。

## 发布前必须全部通过

1. **真实队列证据**：十段日志 `max_queue>=2`、`queue_visible_count>=9`、`handoff_count>=8`，最终 `movement_commands_sent=10`。
2. **连续性**：操作者确认三点两轨迹之间无明显停顿或异常减速；方向和黄色目标一致。
3. **运动状态**：关节无突然大幅变化，无抖动、异响、报警、保护停机或 SDK 超时。
4. **停止与恢复**：运动中松 Grip 能停止并确认队列为空；重新握持从新的实测停止点绑定，不补跑旧目标。
5. **输入故障**：头显追踪丢失、UDP 输入过期、界面心跳中断均不得继续下发。
6. **重复会话**：②退出后能够再次启动遥操作，不需要重启整个环境；①恢复实测数字孪生反馈。
7. **离线回归**：全部 `verify_*.py` 测试、GUI 实开截图、Python 编译和两个中文 CMD 解析检查通过。
8. **GitHub 冷复现**：从 V1.5 候选提交重新克隆到独立 D 盘目录，按文档补本机配置后，先只读再完成同一受限真机验收。

任一项没有证据时不创建 V1.5 标签，也不把开发候选描述为已发布版本。

## 与 V2 的边界

V2 才研究 JAKA `servo_j`、厂家滤波器和固定周期调度。V2 必须重新从零位保持、固定轴小动作和节拍测量开始验收，不能继承 V1.5 厂商运动队列的真机放行结论。

# V1.5 动态采样候选：实现与验证

2026-09-26 起记录动态采样重构。早期条目是离线/只读证据；最终发布边界以
`v1.5.0_下载与复现.md` 和本文件末尾的 2026-09-28 真机结果为准。

2026-09-27 更新：已修正重新移动的合并窗口，动态只读改用原始位姿，

后续行为与验证见 [厂商规划迭代记录](V1.5厂商规划迭代_20260927.md)。

## 操作入口

关闭空闲的旧②窗口，再打开②。窗口底部新增“动态检查最大间隔”两个数字框，
初始为 **5 mm / 1°**。它们控制相邻逆解检查点间隔，不是 TCP 速度、运动段长
或整体姿态范围。参数必须是有限正数，启动时锁定。以后改变间隔后应重新做对照。

1. “新轨迹只读测试”：默认启用动态采样，运行120秒，随时可结束。
2. “新轨迹离线诊断”：选择已有原始手柄 JSONL，输出几何压缩与检查点数对照。
3. “有界意图六维候选（真机待验收）”：独立、显式的 150mm/s 全范围入口，使用 JAKA
   `linear_move_extend_ori`；默认不启动。它使用150 mm/s、400 mm/s²、姿态30°/s、
   启动位置周围100 cm及姿态±30°的原档位约束。本版实际运动效果尚待现场验证。

旧“V1.5正式连续六维”和姿态优先按钮保留旧策略，便于对照。修改动态检查间隔
不会改变旧按钮的控制逻辑，也不会提高新按钮的速度。只读入口保留未限幅原始
姿态用于诊断整圈意图；真机仍经过原有范围约束，因此只读成功不等于全工作空间放行。

## 数据如何流动

手柄有效帧 → 同步的位置/姿态目标 → 有界原始点缓存 → 几何关键点合并 →
自适应 JAKA 逆解检查 → 一份待提交结果 → 读回控制柜预排槽空闲 → 厂商队列执行。

单一线程拥有 SDK。规划期间每轮最多一次逆解，轮间继续检查输入和停止许可；
控制柜仍最多一条执行段与一条预排段。PC额外准备的候选没有进入控制柜。

### 几何选点

- 用位置1 mm、姿态0.25°的预算检查原始点，位置与姿态共用单调路径进度。
- 平滑处选择最长合规前缀；偏离、转弯、折返或段长上限结束合并。
- 不再要求手柄先移动20 mm或转动2°；细小残量可在80 ms等待窗口后进入规划。
- 压缩始终对原始点核对，避免重复压缩时误差累积。
- 截短已批准的弦后保留其剩余端点与原始年龄，不回头追已替代的非匀速中间点。

### 自适应逆解

每个区间按左起点 → 中点 → 右端点顺序调用厂商逆解，以前一个关节解作参考。
最终已检查邻点间隔默认不超过5 mm/1°。根据中点关节曲率、关节变化放大、
限位余量和相邻关节跳变决定是否二分。细分后的下游端点重新求解，禁止复用
不同参考种子得到的关节解。

默认参数定义在 `adaptive_sampling.py`，注释解释各项含义：

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| 细分最小空间/角度尺度 | 0.25 mm / 0.05° | 到此尺度仍有硬风险就拒绝 |
| 中点关节曲率误差 | 0.15° | 触发局部细分，不是实机加速度 |
| 接近限位提醒 / 最小余量 | 8° / 3° | 接近时加密；不足时拒绝 |
| 邻点关节变化 / 单段关节跨度 | 3° / 12° | 沿用既有检查边界，不对关节角取模 |
| 每任务最大调用次数 / 深度 | 256 / 10 | 防止复杂区间无界递归 |
| 每任务时间预算 | 120 ms | 丢弃迟到结果 |

检查只输出 JAKA 的关节解。没有新增自编逆解、Jacobian控制器、伺服滤波或配置写入。
风险细分不是主动绕奇异点规划。有限采样不能证明点间不存在奇异点或碰撞。

### 积压与队列

始终合并几何允许合并的未提交点；200 ms记录压缩压力，300 ms提前暂停，
400 ms保留硬过期边界。原始接收年龄不会因轮询、重复目标或新心跳而刷新。
无法在精度预算内压缩的折返/转圈不会被悄悄删除。暂停后需要松Grip重新捕获。

待提交结果能在控制柜执行期间提前准备。当前SDK读回没有可信的剩余执行时间，
因此不使用“距离/速度”冒充实际剩余时间；提交时使用已有的队列状态条件。
队列满时20 ms轮询，准备结果过旧、起点改变或最新许可撤销均禁止下发。
检查过的最终TCP（含连续RPY表达）原样提交给厂商运动接口。

### 与可导轨迹的关系

已有五次参考曲线可离线检查结点导数连续，但JAKA直线/圆滑接口并不接收这些
多项式系数。新调度减少重复计算、固定起发门槛和等待造成的断供；实际圆滑路径、
速度、加速度连续性必须由实测验证。当前仍沿用厂商5 mm圆滑参数，不声称该值
对所有转角、段长和纯姿态运动都具有同一种几何含义。

## 本次证据

原始输入：`Validation/trajectory_reference/readonly_20260926_163511_016428.jsonl`。
477个原始握持姿态。离线采用120 ms可见窗口，选出243段；几何预算检查失败0。
对同一组选定段，固定2 mm/0.2°需2535个检查点，动态初始检查822个，减少67.6%。
原输入旋转总弧长479.787°，合并后474.299°；预算内小折线被简化，所以弧长不必相等。
这不是J6转角，也不能凭弧长单独证明整圈意图保留。

报告：`Validation/trajectory_reference/replay_20260926_185933_143644.json`。
该报告没有调用SDK。822只是**风险细分之前**的估计，不能拿它与原会话2270次实际
逆解直接宣称实机加速倍数。整圈、反向、局部高曲率、跳变、迟到、重复Grip和
下发目标一致性另有离线故障注入测试。

## 源码阅读顺序

1. `Python/src/vla_lab/adaptive_sampling.py`：统一参数和关键点合并。
2. `Python/src/vla_lab/adaptive_inverse.py`：逐次求解和风险细分状态机。
3. `Python/src/vla_lab/trajectory_horizon.py`：缓存、年龄、原始点残量及候选交付。
4. `Python/src/vla_lab/trajectory_shadow.py`：真实SDK只读集成。
5. `Python/src/vla_lab/adaptive_pose_queue.py`：厂商执行队列适配器。
6. `Python/src/vla_lab/adaptive_replay.py`：无机器人离线对照。

测试用例中的逆解替身只是可控函数，用于制造曲率、跳变、超时与SDK错误，
不代表真实JAKA关节运动。现场下一步是默认5 mm/1°的只读复测，观察积压、
实际调用量和细分次数；再评价新执行模式的停顿、延迟和实际运动。

早期离线回归：`unittest discover -s Python/tests -p 'verify_*.py'` 共388项，

实际Tk界面启动及交互检查通过，新参数框和按钮可见；没有启动机器人子进程。
界面留图为 `Validation/trajectory_reference/adaptive_gui_review.png`。
`git diff --check` 通过。仅用于代码排版的Black工具安装在D盘缓存目录，

C2连续。

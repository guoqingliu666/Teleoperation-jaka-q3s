## 反馈与渲染

②在同一个SDK连接里以30Hz目标节拍采实测关节/TCP，工具/状态5Hz；控制和显示的SDK调用在同一线程串行，不假设实测帧率必然达到30Hz。
读取超过150ms的帧丢弃，不把迟到数据重新标记成新鲜。
Unity每渲染帧以15ms时间常数趋近实测关节；无新数据超过150ms即保持。
HUD分开显示采样Hz、渲染FPS、读取耗时、帧龄。渲染目标90FPS不代表设备一定达到90FPS。
②另把离合锚点、映射矩阵和工作球作为独立显示契约直接发到5006。
Unity分开接收实测状态和目标绑定；每个渲染帧用本地XR算黄色目标，不经过SDK读取循环。
黄色目标保留既有掌面显示偏置；蓝色小球精确标识实测Tool1 TCP，二者不是同一含义。
松Grip/失追踪立即取消本地绑定，旧绑定重发不能复活；须收到②的新绑定。
②目标更新超过0.3秒时HUD提示“黄色仅本地显示、运动状态未知”，不伪造运动或反馈。
②会话运行期间负责发送机械臂实测关节；其余时间由①只读广播。旧控制脚本保留用于追溯，不作为现行②入口。

## JAKA规划与筛查边界

逆运动学接口是厂商kine_inverse；运动是linear_move_extend(target,ABS,False,speed,acc,0)。
姿态保持，零过渡容差，一段到位后取最新目标再规划。不使用servo_j/servo_p，不写FILTER_TYPE。
每2mm检查一次拟执行直线段，前一解作为下一种子，不枚举替代分支、不用取模掩盖大角跳变。
相邻解>3°、段内累计>12°、距配置限位<3°则保持；-4按不可达处理，其它SDK故障结束会话。
运动中检查实测关节与已检查的短段关节范围，偏离>3°即请求停止。
软件阈值是保守工程设置，不是厂商额定能力或形式化安全证明。

限位来自本机配置中`QUEST_JAKA_LIMITS_FILE`指向的导出`usersettings.ini`，日志记录该文件SHA256。
该文件是导出快照；平板修改限位后需重新导出。在线另外检查控制器报警、限位、Tool=1、用户系=0。
不存在“两个端点逆解成功就保证中间安全”的承诺。离散筛查可能漏掉采样间奇异区；
厂商linear_move的实际逆解分支不是Python预检解的逐点下发。实测偏离门槛只能减少风险。
本版无全机碰撞几何规划，不会自行绕开物体，也不会在不可达时突然切分支到另一个姿态。
短段零过渡会在段间减速，不能声称等同连续伺服的无停顿跟随；后台显示和最新输入不会因此停采。
若需要更平滑的路点融合，须核实厂商队列/混合/停止语义和现场轨迹表现后实施。

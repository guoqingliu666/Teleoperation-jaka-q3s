# 停止确认修复与发布边界

依据：`session_20260927_220055_198806.sdk.jsonl` 中第一次motion_abort耗时157.7854ms、返回0。
随后原包装器禁止get_motion_status，导致42条运动命令后的会话无法确认停止。
返回0不能证明队列已清空；本次修复不取消150ms时效门槛。

## 修改

- TracedSdk提供专用get_stop_motion_status，只在该调用期间允许故障锁内读取队列状态。
- 普通查询和所有后续运动保持锁定；停止确认不能清除原故障。
- 专用状态读回若迟到，仍抛错；超过2秒停止确认窗口的结果不能作为确认依据。
- 仍要求inpos且queue、active_queue均为0。原生SDK调用本身不可中断，2秒是结果接受窗口，不是硬实时停止保证。
- 先写停止原因和路径拒绝详情，再请求停止；本次确认前先撤销旧stop_confirmed值。
- 新增停止调用迟到、状态读回迟到、队列始终忙、停止调用异常的离线故障测试。

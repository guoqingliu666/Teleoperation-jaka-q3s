# V1.5 有界意图调度候选

这是开发候选，不是 GitHub 正式 V1.5 发布，也不是已完成现场验收的版本。
运动接口仍为 JAKA `linear_move_extend_ori`，逆解仍为 `kine_inverse`。
没有引入自编机器人逆解、ServoJ/ServoP 或修改控制器滤波参数。

## 用户操作和行为变化

正常结束当前会话后，重新打开②。使用专用按钮：

1. “新调度只读测试（120秒，不运动）”：先松 Grip，再握住移动和转动。
2. “有界意图六维候选（真机待验收）”：现场核对同参数只读报告后，用于操作者启动的真机实验。

候选固定150 mm/s、400 mm/s²、30°/s，位置范围100 cm、姿态范围±30°；
单段上限60 mm/6°，检查默认最大间隔5 mm/1°。这些是软件试验参数，
不是新调度已经通过真机验收的证明。旧入口继续保留原模式。

新增“接纳比例”和受限帧计数。输入持续超过处理能力时，平移与旋转的新增量
按同一比例缩小；未接纳的增量明确计数，不存成未来待执行动作。
因此过载后机器人与原始黄色目标可能有操纵偏移，停手不会追完被丢弃的增量；
松 Grip、再握持从实测 TCP 重新对齐。黄色仍代表原始手柄意图，蓝色仍为实测。
这项取舍用于防止无限历史积压；不能把“零暂停”解释成完整复现所有输入。

## 重构内容

- `intent_horizon.py`：新鲜输入检查与待处理路径分开。缓存最多128点；
  路程/设置速度的名义待处理量限制为0.35秒，在用到一半后逐渐限制新增量。
  这个数不是实际时间延迟或控制器剩余执行时间；已提交队列不包含在其中。
- `adaptive_inverse.py`：协作模式每轮一次 SDK 调用，保留同一候选继续计算；
  不按60ms计算软预算形成运动段。单次调用超过120ms仍拒绝返回值；
  最大调用次数、细分深度、关节跨度、余量和曲率检查仍保留。
- 运动分段由几何、姿态、关节跨度和名义段时间决定。平滑小动作允许合并，
  微小静止尾段最多等待160ms；重要转折仍保留，不为合并跨过未检查路径。
- 准备完的候选依赖固定起点和 Grip epoch；排队年龄本身不再引起重捕获。
  下发前仍核对最新输入许可、实测起点或已提交尾端及控制柜空槽。
- 新候选的接纳目标再次限制在会话启动工作空间内。重复 Grip 不移动工作空间中心。
- 队列深度仍为2。控制线程刚读取的真实关节/TCP供数字孪生复用，保留原查询时间，
  减少重复 SDK 读取。没有用目标关节充当实测反馈。
- 旧 `completed_prefix` 入口补上过期/结束检查。新调度不再用这个恢复入口。

## 验证和证据边界

`verify_intent_horizon.py` 检查持续输入、封闭消费槽、输入断流、过期SDK返回、
计算切片不切运动段、转折、过载后的静止行为、工作空间及重复Grip。
`verify_adaptive_queue.py` 检查真实执行适配器的深度2约束、精确下发已检查目标、
松手撤销、异常停止及满槽时继续规划。机器人均为测试替身。


该工具重放真实输入，使用合成连续关节映射和1.11ms常规/20.74ms尖峰耗时模型，
不加载厂商SDK。宽限位只是替身的数值范围，绝不用于机器人。名义时间消费和
三倍慢消费两种情况里，旧调度各阻断3个窗口，新调度各阻断0个窗口，
最大缓存分别16和55点，没有计算预算导致的短段。
新调度分别有454/493、472/493个输入帧发生了不同程度的增量限制：
说明不积压的代价真实存在，不能宣称所有快速输入都得到一比一跟随。

旧、新模式遇阻断后的输入处理数量不同，候选数和IK总数不能直接作为性能倍数。
替身回放不证明现场可达性、避奇异点、碰撞安全、控制柜圆滑曲线或物理 C2。
